# SENTINEL-X final Neatlogs integration — 11 October 2026

## Scope and implementation

The exporter accepts exactly these nine event names: `project.uploaded`, `finding.submitted`, `agent.inference.started`, `agent.inference.completed`, `patch.generated`, `patch.validation.completed`, `approval.recorded`, `verification.started`, `verification.completed`. There is no Neatlogs Agent B reflection event. The legacy Agent A observer is disabled in the planner and its automatic log capture is off. Existing local Agent B retry behavior remains part of SENTINEL-X; the controlled hosted workflow used attempt 0 and did not invoke it.

Events attach to backend upload, finding creation, Agent A invocation, patch policy, authenticated approval, and verification transitions. Event submission happens outside verdict transactions. A bounded daemon queue of 256 entries isolates the exporter. Failures drop telemetry without changing approvals, test outcomes, or job status. `SENTINEL_NEATLOGS_MODE=off` is the default; `local` captures only a bounded in-memory ring; `hosted` initializes the documented Python SDK destination `https://ingest.neatlogs.com` with log capture, auto-instrumentation, and uploads disabled. The SDK's OTLP HTTP exporter uses a ten-second default request timeout. No application exception text is sent.

Each event carries `event` and a random 128-bit `correlation_id`. Where applicable, it carries a separate random opaque `run_id`, integer `attempt` (including 0), Boolean `success`, integer `duration_ms`, and integer `tests_passed` and `tests_failed`. No internal project, job, or run database ID is exported. Local `telemetry_ids` rows retain the random mapping across backend restarts. Exported span attributes use the SDK-documented `neatlogs.workflow.*` namespace and a final SDK mask strips every other application attribute, all span events and links, resource attributes, and status descriptions. SDK-generated companion spans are dropped by this mask.

Changed code and tests: `backend/lifecycle_telemetry.py`, `backend/workflow.py`, `backend/routes/projects.py`, `backend/database.py`, `agent/planner.py`, `agent/observability/neatlogs_observer.py`, `backend/tests/test_lifecycle_telemetry.py`, `backend/requirements.txt`, `backend/requirements.lock`, and `scripts/neatlogs_hosted_smoke.py`. The original Phase 8 implementation was backed up to `/tmp/sentinel-x-neatlogs-preintegration-20261011.tar.gz` with owner-only permissions. The historical Phase 8 evidence database remains untouched.

## Limitations

The dashboard showed all nine final trace IDs as Ready and displayed the final verification event and allowed execution attributes. Generic correlation search indexing remains unverified. The SDK transport necessarily exposes ordinary network connection metadata to the destination even though SENTINEL-X does not add an IP address to its telemetry payload. Neatlogs retention and residency terms are not verified here. A process crash can lose queued telemetry; the queue is intentionally best effort and cannot change the security verdict. Hosted mode is opt-in per backend process.
